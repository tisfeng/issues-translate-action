# 跨语言代码质量

这些规则适用于手写的 TypeScript、JavaScript、Shell 以及其他源码文件。

## 源码组织

- 当某个区域超过少量文件时，按功能或明确的职责边界组织目录。将功能专属的解析、I/O、
  编排、验证、测试和文档放在一起。
- 每个源码文件聚焦于一个职责；当解析、I/O、编排和验证混杂时，提取同级辅助文件或模块。
- 手写文件通常应控制在 500 行以内。接近或超过该大小时，在新增行为前检查是否需要按职责拆分。
- 手写文件不得超过 1000 行。现有超限文件属于技术债务；不要在没有具体拆分计划时继续加入
  复杂流程。
- 生成文件、第三方代码、纯数据、模板、大型 fixture 和有意 vendor 的运行时文件不受行数限制。

## 命名与实现

- 遵循各语言和工具链的常规命名约定。
- 对不参与导入的文档、导出产物、Action 管理的运行时路径和独立脚本使用 kebab-case，除非
  周边工具要求其他格式。
- 新增或重命名类型、函数、属性、参数和局部变量时，使用清晰简洁的名称，移除重复上下文，
  通常控制在 20 个字符以内。
- 除简单循环索引外，避免单字母变量。
- 除非语言、模块或领域模型确实需要，否则避免全局 helper、类型级函数和可变全局状态。
- 不要为未复用且没有明确语义的一次性字面量提取变量或常量。
- 在代码库已经采用 async/await 的地方优先使用它，而不是回调。

## 文档注释

- 为非简单脚本或模块添加文件级注释，说明入口、职责和重要副作用。
- 为复杂函数、命令入口、解析器、I/O 边界和恢复逻辑添加简短文档。不要为明显的 accessor 或
  薄 wrapper 添加机械注释。
- 注释应简洁并随行为更新；尽量将每行控制在 80 个字符以内。
- 新建或更新源码文件头时，使用当前 Git 用户名，不能使用 Agent 名称。
