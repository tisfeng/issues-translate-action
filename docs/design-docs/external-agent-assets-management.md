# 外部 Skill 资产统一版本治理设计

- 状态：adopted
- 初次记录：2026-09-09
- 最近更新：2026-09-16

## 背景

本项目需要直接从仓库运行共享 Skills，并让安装内容可离线审查和历史复现。只引用全局目录
缺少稳定证据，项目各自修改副本又会产生行为和安全差异。

## 设计决策

采用“外部版本化权威来源 + 仓库内完整快照 + lock 内容校验 + 宿主规则保留项目差异”：

- 外部仓库统一维护通用内容，项目提交可离线读取和运行的完整快照。
- lock 记录来源和预期哈希，通过重算检查本地漂移，而不替代实际安装内容。
- 项目特有的 Action 事件、外部写入、测试和打包边界继续由宿主文档定义；通用 Git、Review 和
  交付算法由受管 Skill 维护，不通过本地修补或 fork 改写。
- 上游停止发布项目级 Codex 子代理后，本项目只保留平台无关的六个 Skills。
- `fireworks-tech-graph` 未被本项目采用；若未来需要，应作为独立授权任务评估版本、许可证、
  体积与运行时依赖。

现行治理规则以 [`docs/agents/README.md`](../agents/README.md#外部-skill-资产) 为准；上游版本和
同步命令记录在 [`docs/references/tisfeng-skills.md`](../references/tisfeng-skills.md)。

## 取舍

- 仓库会保存完整外部快照，以换取离线可用、可审查和可回滚。
- 固定 tag 与 peeled commit 会增加同步工作，但避免可移动引用造成不可复现结果。

## 重新评估条件

- 安装器改变 lock、hash 或安装目录。
- 上游改变仓库、发布方式或 Skill 路径。
- 项目差异无法继续由宿主规则表达。
