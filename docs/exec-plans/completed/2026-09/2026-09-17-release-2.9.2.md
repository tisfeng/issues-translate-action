## 背景

`v2.9.1` 之后修复了翻译机器人自身评论仍进入语言检测的问题，并完成仓库 Agent/Skill 治理整理。
用户明确要求使用 `$release` 发布 `2.9.2`。

## 目标与范围

- 目标结果：将 `92f09e4db5411aea294862418b746c52ccb3a653` 发布为 stable Latest `v2.9.2`。
- 允许修改路径：本计划及 `docs/histories/2026-09/2026-09-17-release-2.9.2.md`。
- 同任务 history：`docs/histories/2026-09/2026-09-17-release-2.9.2.md`
- 允许外部操作：快进推送 `origin/main`、创建并推送 annotated tag `v2.9.2`、创建同名 GitHub Release。
- 用户限制：不 force push，不修改既有 tag、Release 或其他仓库。
- 非目标：不修改产品源码、依赖、构建产物、workflow 或 Marketplace 状态。
- 验收标准：远端 `main` 与 tag 指向候选 SHA，Release 为公开 stable Latest，归档包含 Action 入口。

## 工作计划

1. 冻结候选 SHA，核验工作树、远端分支、目标 tag/Release 和 GitHub 身份。
2. 运行 format、test、build、lint、package 和差异检查。
3. 写入前重新核验远端状态，依次推送分支、annotated tag 并创建 GitHub Release。
4. 重新读取分支、tag、Release 和源码归档，完成 history 与本地记录提交。

## 风险与决策

- 目标版本为稳定 patch release，按当前上一稳定版为 Latest 的状态，将 `v2.9.2` 显式设为 Latest。
- Release notes 只说明翻译机器人自身评论修复；内部 Agent/Skill 治理不作为用户可见功能发布说明。
- 首次 push 命令因未跟踪路径显示断言不匹配而在远程写入前停止；确认远端未变化后修正断言并成功推送。
- 所有远程对象均在单次成功写入后转入只读核验，没有重复 tag 或 Release 操作。
